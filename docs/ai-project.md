# Проект для ИИ: «Знакомая вода»

Описание устройства проекта, написанное для агента, который собирается тут
работать. Правила работы (язык, гейты, коммиты, доказательства) — в
[`AGENTS.md`](../AGENTS.md). Здесь — **что это за система и как она устроена**.

## 1. В двух абзацах

Браузерный симулятор морской рыбалки. Игрок сидит в лодке, выбирает точку лова,
забрасывает удочку, вываживает рыбу, продаёт улов и берёт заказы. Мир — двенадцать
акваторий от бухты до ледяного шельфа и бездны, в каждой по три точки; 301 вид рыбы
в пяти томах кодекса; погода, сезоны, фазы луны, ветер, события моря.

Это Next.js-приложение, но игра живёт не в DOM: всё, что видит игрок на воде,
рисуется Canvas 2D по кадру. Сервер нужен для аккаунтов, облачных сохранений,
рейтингов и мировых рекордов.

## 2. Стек и запуск

| Слой | Технология |
| --- | --- |
| Приложение | Next.js 16 (App Router, Turbopack), React 19, TypeScript 5.9 |
| Стили | Tailwind CSS 4 + собственный `game-ui.css` |
| Сцена | Canvas 2D, ручной рендер по кадру; 3D-лодка на `three` (по умолчанию выключена) |
| Звук | процедурный WebAudio, без файлов |
| Данные | Postgres через Drizzle ORM; схема и RLS — `supabase/*.sql` |
| Тесты | `node:test` через `tsx` |
| Деплой | Vercel из `main` + workflow `.github/workflows/water-production.yml` |

```bash
npm ci && cp .env.example .env.local   # DATABASE_URL нужен серверу, не сцене
npm run dev                            # http://localhost:3000
npm test                               # 252 теста, 1 skip без TEST_DATABASE_URL
npm run build && npm start             # прод-сборка
```

Без базы игра всё равно запускается: `/api/auth/me` отвечает 503, приложение уходит
в офлайн-ветку «сохранение на устройстве». Это удобно для проверки сцены.

## 3. Доменная модель

| Сущность | Где | Смысл |
| --- | --- | --- |
| `LocationDef` | `src/game/world.ts` (`LOCATIONS`, 12) | акватория: климат, глубины, берег, набор событий |
| `SpotDef` | `world.ts` (`SPOTS`, 36) | точка лова: глубина, грунт, рыба, якорные координаты |
| `BoatDef` | `world.ts` (`BOATS`, 9) | судно: класс, скорость, трюм, цена |
| `FishDef` | `fish.ts` + `fish2..5.ts` (`FISH`, 301) | вид: глубина, редкость, сезон, цена, вес, наживки |
| `PortDef` | `world.ts` (`PORTS`, 5) | порт: спрос, цена, таверна, доработки |
| заказ | `engine.ts`, `Panels.tsx` | `single` / `bulk` / `bundle` / `trophy`, срочные, уровни, отказы |
| событие | `src/game/events/*` | 50 явлений моря: когда, чем обернётся, что даёт |
| погода | `src/game/atmosphere/*` | 12 видов, марковская цепь по сезону и климату |

Сохранение — один JSON (`SaveState` в `src/game/types.ts`): прогресс, лодка,
снаряжение, кодекс, деньги, задания, заказы, флаги событий. Хранится локально и
в базе; конфликт решается по `stats.playSeconds`, ответ `409` при попытке
перезаписать более свежее.

## 4. Как устроен кадр

```
Engine.update(dt)                 → состояние: время, лодка, заброс, клёв, события
Scene.render(ctx)                 → собирает Frame и вызывает рисующие модули
  frame.ts                        → контракт «кадр ↔ мир»: viewLeft, viewWidth, hY, sY, sc
  aquatoryStream.ts               → что вообще прогружено (чанки 600 px)
  sky → cloudBank → land → port → water → seabed → boat → ambient → eventFx → hud
```

Три координатных системы, которые нельзя путать:

1. **Мир акватории** — `waterWidth(loc) = точки × 2400`, до 7200 px.
2. **Кадр игрока** — `viewLeft … viewLeft + viewWidth`, обычно 720–1440 px.
3. **Экран** — пиксели канваса с учётом `sc` (масштаб сцены от размера окна).

Правило проекта: всё, что считается и рисуется, привязывается к кадру. Мир
существует, чтобы у объектов были устойчивые абсолютные координаты (берег не
дрожит при движении камеры), но обрабатывается только видимая его часть.

## 5. Две фоновые системы

| | `render/ambient.ts` | `render/eventFx.ts` |
| --- | --- | --- |
| Что | постоянная жизнь: грузовоз, сейнер, парусник, каноэ, птицы, косатки, дельфины, тюлени | то, что запустил режиссёр событий |
| Когда | само, по таймеру 14–36 с, максимум три истории | по расписанию `EventDirector` |
| Где | горизонт и полоса моря, глубина плана `PERSP` | у лодки: якорь, фазы, затухание |
| Скорость | `passerSpeed(kind, p, sc)` | `EVENT_FX_MOTION_SCALE` |

Глубина плана `p` — одна точка правды: по ней считается и размер при отрисовке
(`this.pOf(h)`), и скорость хода. Поэтому судно на горизонте ползёт, а дельфины у
борта идут бодрее, и всё это без разнобоя между функциями.

Порядок отрисовки фона — по `pOf`, а не по сырому случайному `p`: ближние истории
перекрывают дальние.

## 6. События моря

`EventDirector` (`events/director.ts`) планирует интервал 520–1160 игровых минут,
держит ротацию категорий, цепочки (чайки → косяк → дельфины), фазы
(предвестие → нарастание → пик → спад), выборы с наградами и баффы на клёв, цены,
опыт. В сохранении живёт JSON v2 внутри старого поля `events`; миграция v1 → v2
внутри модуля, схема БД не менялась.

Сцена получает от режиссёра список видимых событий и рисует их в `eventFx.ts`
с якорем у лодки: эффект обязан попадать в кадр, иначе игрок видит карточку события
и пустое море.

## 7. Атмосфера

`src/game/atmosphere/*` — чистая модель без DOM: астрономия (высота солнца и луны
по широте), сезоны, 12 видов погоды марковской цепью, температура, ветер с
порывами, осадки по температуре, палитра неба/моря/суши. Сцена и экран входа
только читают её состояние.

## 8. Интерфейс

`src/components/game/*`: `Game.tsx` владеет `Engine` и `Scene`, панели — отдельные
компоненты (`Panels`, `Codex`, `Journal`, `Travel`, `WorldAtlas`, `LocalNavigation`,
`PortHub`, `SettingsModal`, `Account`, `Friends`, `Aquarium`, `CoolerModal`).

Ориентиры: титульный экран показывает живую сцену у последней позиции игрока,
панель перемещения — местные точки и рыбалка рядом, заказы — четыре вида с
уровнями и отказами. Мобильная раскладка обязательна: те же панели в узком окне.

## 9. Сервер и данные

- `/api/auth/*` — регистрация по логину и паролю (scrypt + соль), сессия в
  httpOnly-cookie, в базе только SHA-256 от токена.
- `/api/save` — проверка конфликта и запись в транзакции.
- `/api/catches`, `/api/leaderboard` — уловы и рейтинги; у улова есть `cid`,
  поэтому офлайн-улов не теряется и не задваивается при повторной отправке.
- `src/lib/sanitize.ts` — сервер пересчитывает прогресс по правилам игры, а не
  доверяет клиенту: наигранное время, число уловов, виды, опыт, глубина.
- `supabase/schema.sql` + `security.sql` — схема и RLS; `npm run db:migrate`
  применяет их и проверяет колонки.

## 10. Инварианты (нарушение = регресс)

1. Мир не меняется от оптимизаций: геометрия, силуэты, расстановка, поведение.
2. Всё считается от вьюпорта игрока; чанк — 600 px.
3. Случайность — только `rng()`, у подсистем свои потоки; `Math.random()` нельзя.
4. Один кадр не зависит от частоты кадров: всё через `dt`.
5. Сцена не падает: сбой звука или отдельного слоя не должен замораживать игру.
6. Отладочные хуки `__zv*` — только в разработке.
7. Сборка не зависит от внешних CDN; шрифты локальные через `@fontsource`.
8. Сохранение с клиента не доверяется: сервер пересчитывает.

## 12. Диагностика без браузера

| Скрипт | Что отвечает |
| --- | --- |
| `scripts/ambientspeed.ts` | секунды на проход и px/с для каждой истории фона |
| `scripts/fxspeed.ts` | смещение элементов эффектов событий за секунду |
| `scripts/worldsignature.ts` | изменился ли мир |
| `scripts/check-prices.ts`, `show-prices.ts` | экономика улова и заказов |
| `scripts/render-auth-scene.tsx` | автономный `auth-scene.html` со сценой входа |

Если нужен браузер, в разработке есть `window.__zv` (движок), `__zvScene` (сцена,
включая `life` — фоновую жизнь) и `__zvSound` (звук). Через `__zvScene` удобно
поймать конкретную историю и померить её скорость по `x0 + vx · t`.
